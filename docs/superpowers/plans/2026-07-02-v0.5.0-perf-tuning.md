# v0.5.0 Benchmark-Driven Performance Tuning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the benchmark suite's two real Behind gaps (bundle-size vs tanstack-form, array-ops vs tanstack-form Svelte), harden the PR regression gate against CI-runner noise, and sweep the Tied gaps for opportunistic wins.

**Architecture:** Four independent tasks, each ending in a verifiable state: Priority 0 rewrites `compare-baseline.ts` to compare a median of N samples instead of one noisy sample. Priority 1 items are root-caused already (this plan was written after the investigation, not before) — bundle-size gets a `Tradeoff` annotation (the gap is architectural: neutro's single-closure `createForm` can't be tree-shaken, verified with an esbuild metafile), array-ops gets a real engine fix (extend `shiftStateIndices` to cover `pathSubscribers`, not just error/touched/dirty state) plus a benchmark-harness fix (the Svelte array bench section was measuring itself unfairly coarsely). Priority 2 is a lightweight opportunistic sweep with no code guaranteed.

**Tech Stack:** TypeScript, Vitest (unit + `vitest bench`), Playwright, GitHub Actions, Svelte 5.

## Global Constraints

- No new benchmark surfaces or competitors (per spec's Out of Scope).
- No public API breaking changes; any fix must stay backward compatible.
- Regression-gate hardening (Priority 0) must reduce false positives without weakening real-regression detection — if median-of-3 alone doesn't eliminate false positives at 15%, raise the threshold rather than dropping the sample count.
- Scorecard verdict thresholds (`VERDICT_THRESHOLD = 0.10` in `bench/lib/verdict.ts`) are a different mechanism from the regression-gate's 15% threshold in `compare-baseline.ts` — Priority 0 only touches the latter.
- Every Priority 1 gap ends in one of two states: Fixed (badge improves, verified via `bench:generate`) or Annotated (`bench/annotations.ts` entry with a concrete architectural reason).
- Priority 2: only open a fix for a Tied pair if a concrete, low-risk improvement surfaces during the lightweight investigation pass — do not force a fix, and do not annotate a Tied result (Tied is already accurate, no excuse needed).

Replace the full contents of `bench/scripts/compare-baseline.ts` with:

```ts
import { readFileSync } from 'node:fs'
import type { BenchResults, LibraryBenchResult } from '../types/schema.js'

export const REGRESSION_THRESHOLD = 0.15  // 15%
export const HIGH_VARIANCE_RME    = 10    // skip entries with rme > 10%
export const MIN_VALID_SAMPLES    = 2     // need at least 2 of N samples to compute a median

export interface Regression {
  surface: string
  baselineHz: number
  currentHz:  number
  pct:        number
}

export function median(values: number[]): number {
  const sorted = [...values].sort((a, b) => a - b)
  const mid = Math.floor(sorted.length / 2)
  return sorted.length % 2 === 0 ? (sorted[mid - 1] + sorted[mid]) / 2 : sorted[mid]
}

export interface MedianResult {
  medians: Record<string, number>
  skipped: string[]
}

export function collectMedianOpsPerSec(samples: Array<Record<string, LibraryBenchResult[]>>): MedianResult {
  const surfaces = new Set<string>()
  for (const sample of samples) for (const key of Object.keys(sample)) surfaces.add(key)

  const medians: Record<string, number> = {}
  const skipped: string[] = []

  for (const surface of surfaces) {
    const values: number[] = []
    let sawHighVariance = false
    for (const sample of samples) {
      const entry = sample[surface]?.find(r => r.library === 'neutro/form')
      if (!entry || entry.status !== 'ok' || entry.opsPerSec == null) continue
      if (entry.highVariance || (entry.rme ?? 0) > HIGH_VARIANCE_RME) {
        sawHighVariance = true
        continue
      }
      values.push(entry.opsPerSec)
    }
    if (values.length < MIN_VALID_SAMPLES) {
      skipped.push(`${surface} (${values.length}/${samples.length} valid samples${sawHighVariance ? ', high variance' : ''})`)
      continue
    }
    medians[surface] = median(values)
  }

  return { medians, skipped }
}

export function computeRegressions(
  currentMedians: Record<string, number>,
  baselineCore: Record<string, LibraryBenchResult[]>,
  threshold: number,
): Regression[] {
  const regressions: Regression[] = []
  for (const [surface, currentHz] of Object.entries(currentMedians)) {
    const baselineSurface = baselineCore[surface]
    if (!baselineSurface) continue
    const baseline = baselineSurface.find(r => r.library === 'neutro/form')
    if (!baseline?.opsPerSec) continue
    const pct = (baseline.opsPerSec - currentHz) / baseline.opsPerSec
    if (pct > threshold) {
      regressions.push({ surface, baselineHz: baseline.opsPerSec, currentHz, pct })
    }
  }
  return regressions
}

function readJson(path: string): unknown {
  try { return JSON.parse(readFileSync(path, 'utf8')) }
  catch (e) { console.error(`[compare] cannot read ${path}:`, e); process.exit(1) }
}

async function main() {
  const inputFiles = (process.env.BENCH_INPUT_FILES ?? process.env.BENCH_INPUT_FILE ?? 'results/core.json')
    .split(',').map(s => s.trim()).filter(Boolean)
  const samples = inputFiles.map(f => readJson(f) as Record<string, LibraryBenchResult[]>)
  const baselineRaw = readJson('results/baseline.json') as BenchResults

  const { medians, skipped } = collectMedianOpsPerSec(samples)
  const regressions = computeRegressions(medians, baselineRaw.core ?? {}, REGRESSION_THRESHOLD)

  if (skipped.length) console.log(`[compare] skipped (insufficient valid samples): ${skipped.join(', ')}`)
  if (!regressions.length) {
    console.log(`[compare] no regressions found (median of ${inputFiles.length} sample(s))`)
    process.exit(0)
  }

  console.log(`[compare] ${regressions.length} regression(s) found (median of ${inputFiles.length} sample(s)):`)
  for (const r of regressions) {
    console.log(`  ${r.surface}: ${r.baselineHz.toFixed(0)} → ${r.currentHz.toFixed(0)} ops/s (-${(r.pct * 100).toFixed(1)}%)`)
  }

  const token = process.env.GH_TOKEN
  const prNumber = process.env.PR_NUMBER
  const repo = process.env.GITHUB_REPOSITORY

  if (token && prNumber && repo) {
    const rows = regressions.map(r =>
      `| ${r.surface} | ${Math.round(r.baselineHz).toLocaleString()} | ${Math.round(r.currentHz).toLocaleString()} | **-${(r.pct * 100).toFixed(1)}%** |`
    ).join('\n')

    const body = [
      '## Benchmark Regression Detected',
      '',
      `> Threshold: 15%. Median of ${inputFiles.length} samples per surface; entries with rme > 10% or fewer than ${MIN_VALID_SAMPLES} valid samples are skipped.`,
      '',
      '| Surface | Baseline (ops/s) | Current (ops/s, median) | Delta |',
      '|---|---|---|---|',
      rows,
      '',
      skipped.length ? `**Skipped (insufficient valid samples):** ${skipped.join(', ')}` : '',
    ].filter(Boolean).join('\n')

    await fetch(`https://api.github.com/repos/${repo}/issues/${prNumber}/comments`, {
      method: 'POST',
      headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({ body }),
    }).catch(e => console.warn('[compare] PR comment failed:', e))
  }

  if (process.env.BENCH_HARD_FAIL === 'true') {
    console.error('[compare] exiting 1 (BENCH_HARD_FAIL=true)')
    process.exit(1)
  }
  process.exit(0)
}

main()
```

### Task 2: Bundle size vs tanstack-form — annotate as architectural tradeoff

**Files:**
- Modify: `bench/annotations.ts`

**Interfaces:**
- Consumes: `ANNOTATIONS: Record<string, Record<string, string>>` (existing map, unchanged shape).
- Produces: nothing new — this task only adds data to an existing export.

This gap is already root-caused (not a fresh investigation): built both fixtures' bundles with esbuild's metafile and inspected input sizes.

- `bench/fixtures/bundle/neutro.ts` pulls in the entirety of `packages/core/dist/index.js` (one 33KB monolithic file — `createForm` is a single closure factory containing array ops, DOM bridge, persistence, computed fields, and devtools hooks all in one function body) — esbuild's tree shaker cannot drop any of it, since nothing in a single function scope is a separately-eliminable export.
- `bench/fixtures/bundle/tanstack.ts` pulls in `@tanstack/form-core`'s `FormApi.js`, `FieldApi.js`, `FormGroupApi.js`, `utils.js`, plus several `@tanstack/*` support packages — its *raw* pre-minification source is larger than neutro's (100KB+ across files vs neutro's 33KB single file), but its modular file/export structure lets esbuild's tree shaker drop unused code paths, producing a smaller final bundle (6.3 KB vs neutro's 10.0 KB gzip).

This is the same category as the existing `async-latency` debounce annotation: a genuine architectural tradeoff (`createForm`'s single-closure design, which is what makes the O(1) dependency graph and unified state management possible) that a non-breaking patch-level task cannot fix without a large redesign (splitting the closure into tree-shakeable submodules) — out of scope per this plan's Global Constraints (no breaking changes).

### Task 3: array-ops vs tanstack-form (Svelte) — engine precision fix + harness fix

**Files:**
- Modify: `packages/core/src/index.ts` (`shiftStateIndices`, `arrayRemove`, `arrayInsert`)
- Modify: `packages/core/test/form.test.ts`
- Create: `bench/apps/svelte/src/NeutroArrayItem.svelte`
- Modify: `bench/apps/svelte/src/NeutroArraySection.svelte`

**Interfaces:**
- Consumes: `pathSubscribers: Map<string, Set<PathSubscriber>>` (existing), the descendant-cascade fix in `notifyPathSubscribers` (already shipped in v0.4.4 — this task builds on it, does not modify it).
- Produces: `shiftStateIndices(basePath, fromIndex, action, targetIndex?): string[]` — same signature, now also includes renamed `pathSubscribers` keys in its returned array (previously only covered error/touched/dirty/wasSet state keys).

This gap is already root-caused (not a fresh investigation) — two independent causes, both already known from the notify-cascade-fix work (`docs/superpowers/specs/2026-07-01-notify-cascade-fix-design.md`, which explicitly deferred this precision work here):

1. **Engine over-notification**: `arrayRemove`/`arrayInsert` call `notify(targetPath)` on the *whole array* in addition to their shifted-key notifies, so once `notify()` cascades to descendants (shipped in v0.4.4), every item's per-field subscriber re-fires on every array mutation — not just the ones that actually shifted position. `arrayMove`/`arraySwap` are unaffected — they already notify only the specific indices involved.
2. **Benchmark harness mismatch**: `bench/apps/svelte/src/NeutroArraySection.svelte` subscribes to the *whole* `items` array via one `useSvelteFormPath(arrayForm, 'items')` call, incrementing a render counter for every item on every mutation. `bench/apps/svelte/src/TanStackArraySection.svelte` uses a per-item `form.Field` snippet that only increments when that specific item's own field re-renders. This is an unfair comparison — Vue's and React's neutro sections have the same whole-array-subscribe pattern, but their competitors (`vee-validate`, `react-hook-form`, `tanstack-form (React)`) measure the same way, so those comparisons are fair; only the Svelte side has a competitor (TanStack Svelte) that measures more finely than neutro's harness does.

Converting the harness to per-item subscriptions without fixing engine over-notification first would have surfaced real stale-value bugs (pre-v0.4.4, `notify()` didn't cascade to descendants at all) — that dependency is why this was deferred here rather than fixed alongside the harness originally.

```ts

      // Also compute renamed keys for any actively-registered subscriber path under this
      // array index, even when no error/touched/dirty/wasSet state exists there - otherwise

      // except by falling back to notifying the whole array (which, since notify() cascades

      for (const key of pathSubscribers.keys()) {

        const match = remaining.match(/^(\d+)(.*)$/);
        if (!match) continue;
        const index = parseInt(match[1], 10);
        const tail = match[2];
        if (action === 'remove') {
          if (index === fromIndex) continue;
          if (index > fromIndex) shiftedKeys.push(`${arrPrefix}${index - 1}${tail}`);
        } else if (action === 'insert' && targetIndex !== undefined) {
          if (index >= targetIndex) shiftedKeys.push(`${arrPrefix}${index + 1}${tail}`);
        }
```
